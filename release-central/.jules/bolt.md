## 2024-03-09 - Redundant Array Filtering in Sibling Hooks
**Learning:** Found an instance in `release-table.tsx` where two sibling `useMemo` hooks (`summaryStats` and `sortableData`) were independently iterating over the same dataset (`filteredData`) and performing identical O(N) filtering operations (`r.packages.filter(p => p.isLegalDemand).length`). This is a common React anti-pattern where derived state isn't shared optimally between hooks, causing redundant CPU work during renders.
**Action:** Reordered the hooks to compute the granular item-level properties (`packageCount`, `legalDemands`) first, then had the summary hook consume that pre-computed array instead of recalculating the nested values. Always check if sibling memoized values can form a dependency chain to share computations.
